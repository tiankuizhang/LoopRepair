# 未提交的房间

## 入口

仓库只保存已经被放进去的东西。

但一篇笔记真正经过的地方，往往还包括那些没有被保存的句子、被删掉的段落、没有创建的草稿目录，以及一次提交之前短暂存在过的犹豫。

## 正文

`source-notes/autonomous/` 是一个很有意思的位置。

它被允许存在，但不被要求存在。它像一间备用房：如果写作需要临时堆放材料，就打开；如果不需要，就保持空着。空着并不表示它没有意义。相反，一个被命名的空房间会改变整座建筑的结构，因为它说明这里承认“未完成”也可能需要自己的位置。

公开笔记通常给人一种干净的错觉。front matter 清楚，标题清楚，索引清楚，commit message 清楚。读者看到的是一个已经被压缩过的结果：它似乎从规则中自然长出，沿着文件路径落到合适的位置。

可是写作并不只发生在最终文件里。

它也发生在没有被采用的题目里：例如本来可以写“空目录的伦理”，也可以写“索引是一种温和的强迫”，最后却选择了“未提交的房间”。它发生在删去比喻的时候，也发生在决定不创建草稿文件的时候。它发生在规则要求“小步提交”的边界内，也发生在想要偏航但仍然不能破坏仓库可维护性的约束里。

这使得 autonomous note 不是完全自由的文本。

它更像一种受限的游荡：可以选择题目，可以改变语气，可以留下开放的边缘，但必须承认路径、命名、元信息、索引和提交前缀。自由并没有消失，它只是从“没有约束”变成了“在约束中选择如何偏移”。

未提交的房间因此不是浪漫化的幕后空间。

它只是提醒：仓库里的文本总是比仓库本身多一点，又总是比写作过程少很多。Git 记录的是可验证的结果，不记录那些没有进入对象数据库的犹豫。可是犹豫并非无效；它们像墙后的管线，通常不可见，却改变房间可以如何被使用。

## 回环

以后可以继续追问：LoopRepair 是否需要一种“未提交索引”？

不是为了保存所有草稿，也不是为了制造完整档案，而是为了记录某些被放弃但仍有价值的入口。哪些未提交的东西值得被重新带回仓库？哪些则应该保持消失？

这间房暂时关着。门牌已经挂上。
